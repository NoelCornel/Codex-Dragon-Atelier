# 可读性与人物清晰度修订 · 2026-10-08

本记录对应 v0.1.0-beta.3；《可读性与双角色实施指导》是模型建议，本文件和源码才是实际实现。用户指出的新生成 Q 版观感诡异、边缘有锯齿，已撤回该素材，未进入构建或发布包。原图、生成候选和施工前备份均保留。用户随后要求更高清、更大且朝内；现已采用 ApprenTice 公开高清Q原图的透明衍生，详见《高清Q素材与排布》。

## 已定位的问题与实现

| 实际原因 | 修订 |
|---|---|
| 原 Q 图集虽为 1536×2288，单格只有 192×208；放大到 280px 不能获得更多细节 | 早期恢复原版并限制192px；现改为941×1672公开高清Q的透明衍生，仍限制原像素与对齐物理位置 |
| 低透明度、brightness/saturate 与中央遮罩叠加，使人物更糊 | 移除调暗/去饱和滤镜；首页 .96、会话 Q .78 / 正常立绘 .80；中央遮罩降到 18% |
| contenteditable 的 placeholder 实际由 p.placeholder[data-placeholder]::before 生成，并有 .5 opacity | 实际伪元素使用实色与 opacity:1，保留字体指标 |
| 外层 composer 没有圆角，内层 [data-composer-body] 才有原生 22px 圆角 | 外层透明且无阴影；描边、实体底色和焦点环作用于内层，不另设圆角/尺寸 |
| 侧栏 nav 在根变量之后再次把 --color-text 定义成 85% 紫色混合 | 在本项目标记的侧栏 nav 内纠正局部别名，普通标题使用正文实色，强调按钮继续用清晰的链接色 |
| 菜单创建时 opacity:0，待动画结束不一定触发观察器 | 创建时即标记语义菜单/对话框，不等待它可见才上色；隐藏菜单不会绘制 |
| 旧匿名预览用大块底色盖住内容，可能制造与真实 UI 不同的亮色条 | 新预览仅临时替换文本节点，保留真实表面、字体和控件；拍摄后恢复文字 |

深色为暖石灰黑，浅色为纸感暖灰；不是纯黑/纯白。紫色是强调与轮廓，不把所有文字染紫。功能边界用独立 controlBorder，装饰细线不冒充控件边界。源码共 85 个已核对的原生变量绑定，另有导航局部别名纠正；危险、成功、警告、info、diff、终端色不覆写。

## 字体、内容与角色

保留原生字体家族、字号、字重、行高。实际在编辑器比对改造前后指标，而不是按模型估计强行加粗全局。正文、次级、三级、链接、placeholder 和按钮文字分别指定职责；输入底部小字局部使用更清晰的次级色。正文表面实体遮挡人物，代码表面由 code 职责控制；语法高亮保留原生语义，未声称逐类高亮都已验收。

正常立绘为用户确认的“年轻成年 / 成熟成年，两种气质”。参考实际 DSH Maid Atelier 两图的相向视线、左侧展开手势、右侧记事姿态及共同落脚线，不照搬少女/更幼小角色或 Flash/Pro 模型关系。右侧高度为左侧的 .94，保持自然差异，避免巨人/小人式悬殊。两张 941×1672 透明生成衍生图保留原设服装和来源署名，不绑定官方模型。

Q版现用ApprenTice公开的941×1672原图去背景，左原向右、右CSS镜像向左，同姿态朝内布局、等大；不是两张独立动作。当前首页宽265.754 CSS px，较原192px帧的153.6 CSS px更大，且输入保持28px空隙。作者提示词与图像已检索核对，不再照搬此前被否定的生成Q。详见[高清Q素材与排布](高清Q素材与排布.md)。

## Opus 建议的核验与取舍

经用户授权使用本机既有 Wawazz messages 链路调用 claude-opus-5-5。首次长回复到 max_tokens 截断，仅 A–G 完整；随后只补齐 H 色表，第二次为 end_turn。两部分原文均保存到指导文件；返回标识不独立证明底层模型身份。

采用表面/文字职责划分、低饱和暖中性底、明确轮廓、取消多重调暗和自然成人差异。模型建议的边界有约 2.1/2.2:1，却标作达标，已独立纠正：controlBorder 深 #9b8dae / 浅 #796b84；focus 深 #c4b3da / 浅 #6e5585。不采用全局 vh 人物尺寸、提高 composer z-index、未知 class 广泛选择器、随意更改原生字号字重，以及把生成图像大文件等同于好画质的说法。

按定义的 9 种实体阅读表面实算：文字最低深 4.627:1、浅 4.592:1；功能边界与焦点最低深 3.837:1、浅 3.351:1。装饰线、disabled、全部原生语法色和人物覆盖后的任意像素不包含在这些数值中，不构成整个客户端 WCAG 认证。

## 验证与剩余边界

实际当前 Store Codex 26.1002.6548.0、Node 24.16.0、屏幕 DPR 1.25。轻量配色真实导入；两版、两模式首页/输入/菜单/设置/移除/聊天滚轮检查，另外按实际 DOM 检查占位符 opacity、输入框圆角、侧栏文字和发送按钮视觉状态，不发送消息。模拟缩放覆盖 100%、125%、150%、200%，不能代替实际多屏及操作系统缩放切换。完整范围见 VALIDATION。

用户进一步说明白色周边主要指低分辨率和边缘锯齿；没有证实某个原生控件固定残留白底。外观/通用设置检查未复现大块近白不透明表面，不据此宣称全部白底问题已修复。旧Q素材本身像素较少，已换为公开高清图的透明衍生，不能凭CSS恢复旧帧缺失的细节。新cutout仍有低alpha边缘像素，实际大小检查未见明显亮边，不声称任意放大都完美。正常生成立绘仍是候选同人画，不把自动检查通过当作用户审美认可。

历史屏幕中心置顶覆盖没有复现或找到可证明的故障现场。主题只在聊天 DOM 内放置 inert、pointer-events:none 的 z0 背景，不创建桌面置顶层；历史开屏播放器原因仍未证实。

本轮滚轮检查曾因固定500ms等待失败。关闭主题的对照同样出现延迟，最终原生/有主题均能滚动；一次CDP输入及观察序列总用时约6.0s/5.1s，包含协议与调用等待，不等于纯用户界面延迟测量。后续验收逐次读取实际位移，避开嵌套工具输出滚动区；功能检查不证明不存在性能问题，也不证明历史桌面遮挡已修复。
